# FreeBank app v0.2.4

Your phone reaches FreeBank whenever your computer is on, with no window open: FreeBank can start when you log in, and
starts its node when your phone asks. And from this version on, FreeBank updates itself.

## What's new

- **FreeBank updates itself.** When a new version is out, FreeBank says so at the top of the window (and Settings >
  App updates checks on request). **Update and restart** downloads it, checks it, puts it in place and opens it:
  - **the AppImage and the Mac app** replace themselves;
  - **the `.deb`** is updated by Software Updater once FreeBank's apt repository is set up
    (https://apt.ecxfreebank.com), or with the new `.deb` from the release page, which FreeBank links to.

  The AppImage and the Mac app take an update only when the release's `SHA256SUMS` carries the release key's signature
  and the package matches its line there: the same check FreeBank makes before installing the node. A release is
  offered once it is signed, never before. (apt checks its repository's own key, as before.) The restart waits until
  nothing is being done to the node, then closes FreeBank the usual way: your node stops and starts again with it,
  unless "Keep running" is on. Like closing and opening FreeBank, it turns "Let my phone send" off: turn it on again in
  Settings > Phone.
- **Start when I log in** (Settings > Phone, under "Keep my phone connected when FreeBank is closed"). FreeBank's
  background part starts when you log in (a LaunchAgent on a Mac, an autostart entry on Linux), with the phone link
  only and the node off. Turning it off, or "Keep my phone connected" or "Keep running", removing your last phone,
  Remove FreeBank and Obliterate all remove the login item.
- **Wake on demand.** When a paired phone opens FreeBank (its session, and Face ID if you set it up), the background
  part starts the node. Until the node answers, the phone shows "Your desktop is starting FreeBank…" and keeps trying;
  the balance shows seconds later. After 30 minutes with no phone session, the node it started stops again.
  If the node can't start, the phone says so, and FreeBank waits two minutes before trying again.
- **What works with no window open:** the balance, history and Receive. Sends need the passphrase, which a background
  part started at login doesn't have, so the phone asks you to open FreeBank on the desktop first. (Closing the window
  with "Let my phone send" on still hands the passphrase over.)
- **README:** the FreeBank node needs macOS 14 or later on Apple Silicon, and macOS 15 or later on Intel Macs.

## Upgrading from v0.2.3

This one you install by hand, as before: the `.deb` (or Software Updater, with the apt repository), the AppImage, or the
`.dmg`. From v0.2.4 on, FreeBank offers its own updates.

## Security self-audit

What v0.2.3's audit says still holds. What v0.2.4 adds:
- **The updater trusts only the release key.** The app checks the signature on the latest release's `SHA256SUMS`
  against the key pinned in the app, before it downloads anything else; it reads the version from the package names in
  that signed file and takes only a higher one (no going back to an older version); and it uses the package only if
  its SHA-256 is the one on its line there. No new key and no secret on GitHub: nothing GitHub holds can make an update
  the app accepts, and an update waits until the release is signed.
- **What the signature vouches for:** the release as it was checked before signing (GitHub's build attestations, and a
  byte-for-byte rebuild of the `.deb`). The AppImage and the Mac app don't rebuild byte for byte yet, so for those two
  you still trust GitHub's build machines, as before; now that they update themselves, that build matters more.
- **apt is unchanged:** Software Updater trusts the apt repository's signing key, which the release workflow holds and
  uses when a release is built. The release key doesn't cover it.
- **How it replaces itself.** The download goes beside the app under a fresh name, readable by your account only, and
  is renamed over the AppImage only once it has checked. A Mac app is unpacked from that same checked file beside the
  bundle, checked to be FreeBank at the signed version with its program and for a macOS this Mac has, and exchanged
  with the old bundle in one step (two renames on disks that can't, with the old bundle put back if the second fails).
  No set-id bits, nothing writable by others. It updates only where no other user could swap a file in meanwhile (the
  login item's rule), never replaces a `.deb` install, and never asks for an administrator's password. What an
  interrupted update leaves beside the app is removed at a later start, once an hour old.
- **Around the restart:** it waits while the node is being stopped, installed, updated or rebuilt, then claims it, so
  no stop, install or update of the node starts meanwhile; Obliterate waits for an update under way, and an update
  never restarts a removed app. The
  checksum files the app reads unasked are capped at 64 KiB.
- **One more contact with GitHub:** `SHA256SUMS` and `SHA256SUMS.sig` from the app's latest release, 15 seconds after
  start and every 12 hours (GitHub sees your IP address, as with the node's update check). The package is fetched only
  when you press Update and restart.
- **A test-only switch** (the `update-test` Cargo feature) lets a test build read another address and key from the
  environment. No release enables it; a test checks the release workflow and build scripts.
- **What runs at login:** the app itself as its background part, light: the phone link only. The login item names
  the program as it is, and is refused for a program other users could replace or a Mac app run from where macOS put
  a download aside. A file writable by your own private group (Ubuntu's default umask) counts as yours. Only a paired phone, after its session (and Face ID if set), can start the node; a connection to
  the relay alone can't. On Linux the started node gets its own systemd scope, so logging out stops it cleanly
  instead of killing it.

## Known limits

- **The Mac update hasn't run on a real Mac yet:** the first one will be v0.2.4 to the next version. The AppImage's
  was tried end to end. FreeBank must be somewhere your account can change (Applications, for an administrator);
  otherwise, and when run from the disk image, it links to the download.
- **No going back by itself:** an update replaces the old copy before the new one has started. The Mac app checks the
  macOS version first; if a new version still won't start, the releases page has the previous one.
- **apt** offers a new version as soon as the release is built, before the release key has signed it.
- **Start when I log in** hasn't been tried with a real login yet (GNOME's autostart, a Mac LaunchAgent).
- FreeBank can't wake a computer that is asleep or off.
- **Macs:** the FreeBank node needs macOS 15 (Sequoia) on Intel Macs and macOS 14 (Sonoma) on Apple Silicon. Not yet
  tried on an Intel Mac.
- The AppImage and the Mac app can't be rebuilt byte for byte yet.
- One wallet per app.
