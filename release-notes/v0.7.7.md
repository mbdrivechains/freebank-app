On easynet, the app's FreeBank node syncs again. FreeBank on easynet moved to a new chain on 20 November, which no
public release could follow until FreeBank v1.2.3. This version follows that chain: update the app first, then update
the node to v1.2.3 when the Node tab offers it. A bill now repays at its reference house's price whoever holds it, and
the app says so.

## Download

From the [releases page](https://github.com/mbdrivechains/freebank-app/releases/latest): the `.deb` for Ubuntu and
Debian, the `.dmg` for a Mac, the `.AppImage` for other Linux. v0.2.4 and later offer this update themselves.

## What's new

- **Easynet's FreeBank v1.2.3 chain.** The app follows the FreeBank chain easynet started on 20 November. On easynet
  it doesn't start a node older than v1.2.3; the Node tab says why and offers the update. After the update, the old
  chain's data is set aside, and as in v0.7.6 only the two newest set-aside copies are kept. The wallet and the node's
  settings stay where they are. What you held on easynet's FreeBank before stays on the old chain, which has stopped;
  the faucet pays on the new one.

- **A bill repays at one price, whoever holds it.** From FreeBank v1.2.3, the part of a bill repaid in sECX is priced
  at its reference house's highest ask of the last 30 days, whether a house or a person holds it. Before, a house that
  held the bill priced it at its own ask. The Bills tab, the bill form and the repay screen now say so. They also
  count the 0.5% the node adds by default, so that a rate raised just before your repayment confirms doesn't stop it.
  A phone paired to the app counts the same amount against its limits.

## Honest limits

- Easynet may start new chains again. Each time, the app's FreeBank node on easynet waits for a FreeBank release and
  an app release that follow the new chain, and the Node tab says so meanwhile.
- Tried on Linux on 22 November, from a v0.7.6 install on easynet with node v1.2.2, using FreeBank v1.2.3's signed
  files before their release: the Node tab said the node was too old and offered v1.2.3. The update checked the
  signature, set the v1.2.2 chain's data aside, deleted the oldest copy so two remain, and left the wallet and the
  node's settings in place. The node reached the network's newest block in under a minute and read "In sync" with
  one peer. After a restart, nothing more moved aside.
- This version hasn't run on a Mac yet; v0.7.4 has.
