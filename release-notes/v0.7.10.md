When easynet moves to a new chain your node can't follow, the app now says so plainly, offers the update even if its
window was in the background, and its link takes you straight to the Update button. Nothing changes on mainnet.

## Download

From the [releases page](https://github.com/mbdrivechains/freebank-app/releases/latest): the `.deb` for Ubuntu and
Debian, the `.dmg` for a Mac, the `.AppImage` for other Linux. v0.2.4 and later offer this update themselves.

## What's new

- **The update offer stays current.** The app looks for a new node release every few minutes, but it skipped that
  while its window was behind other windows or on another desktop, so the red box could say "No update is offered
  yet" long after one was out. It now looks again as soon as the window is back in view, and whenever the red box
  first appears.

- **The red box says what happened.** When easynet has moved to a new chain that needs a newer FreeBank node than
  yours, the box says so, names the release the chain needs, and says that updating moves your node to the new chain:
  your wallets keep their keys and addresses, but coins and payments on the old chain don't carry over. Before, it suggested checking that the computer was online.

- **The link goes to the button.** "Update the FreeBank node on the Node tab" now opens the Node tab, where **Update node to …** is.
  It used to open Settings › Node & connection, which has no Update button. The tab scrolls to the button.

## Honest limits

- Found on a Mac running v0.7.8, whose node stayed on an old easynet chain for two days. This version hasn't run on a
  Mac yet.
- Walked on Linux on 28 November: a node left on the 27 November chain showed the red box; once v1.2.8 was listed,
  the box said the network had moved to a chain that needs v1.2.8 and offered the update, and its link opened the
  Node tab with Update node in view. Pressing it moved the old chain aside, started v1.2.8, and the node synced to the
  network's tip (block 42, the same blocks as easynet's own node). The check when a window comes back into view wasn't tested: the walk runs on a virtual display with no other
  windows.
