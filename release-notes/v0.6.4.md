# FreeBank app v0.6.4 "easynet's replay stamp"

The app's eCash payments on easynet now go out: sends from the eCash tab, deposits into FreeBank, and block bids.
Before, easynet's eCash node refused every one of them.

## Download

From the [releases page](https://github.com/mbdrivechains/freebank-app/releases/latest): the `.deb` for Ubuntu and
Debian, the `.dmg` for a Mac, the `.AppImage` for other Linux. v0.2.4 and later offer this update themselves.

## What's new

- **Each network gets its own replay stamp.** Every eCash payment the app makes carries a mark that keeps it from
  being replayed on Bitcoin: a lock time the eCash node treats as final, and Bitcoin never does. eCash beta's node
  takes 499,999,999. easynet's node takes 499,999,998, as eCash mainnet's will, and refuses 499,999,999 as "non-final".
  The app used beta's everywhere. It now stamps 499,999,998 on easynet (and on mainnet when it comes), and still
  499,999,999 on beta.
- **A deposit is one payment in the eCash tab,** "Deposited 2 ECX into FreeBank", with its own fee. Before, it showed
  as two sends, one of 0 ECX and one of the treasury's new value, each with the old treasury's value as its fee
  (26.998 ECX and 24.998 ECX on easynet, where the real fee was 418 sats): the deposit spends FreeBank's treasury
  output, which isn't the wallet's, and the node counts it so. Only the list was wrong; the deposit was always right.
  A deposit that lost the treasury to someone else's in the same block now says it wasn't sent, as Deposit does.

## Honest limits

- A payment the node refused before this update never went out, and its eCash is still in the wallet. The app said it
  "may have gone out", as it does whenever the node doesn't take a payment cleanly.
- Tested against both nodes on a private test chain (regtest): each takes its own stamp and refuses the other's. On
  easynet itself, a send, a 2 ECX deposit (credited on FreeBank: 1.99999 sECX) and a block bid all went out with
  499,999,998.
- Not yet run on a Mac.
